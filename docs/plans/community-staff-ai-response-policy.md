# Community 관리자 답변 시 AI 자동 응답 억제

## 배경

현재 Community Poller는 질문자와 TechFlow-Assistant가 아닌 모든 작성자를 `STAFF`로 분류하고 `responseRequested=true`로 전달합니다. 이 때문에 관리자가 질문자에게 직접 도움을 주는 답변을 남겨도 AI가 다시 답변하여 내용을 반복하거나 관리자 답변을 불필요하게 덮을 수 있습니다.

## 목표

관리자·지원 담당자의 일반 답변은 대화 문맥에는 보존하되 AI가 자동으로 반응하지 않도록 합니다. 관리자가 AI 검토가 필요하다고 명시한 경우에만 AI 답변을 생성합니다.

## 구현 범위

- 질문자, TechFlow-Assistant, 관리자·지원 담당자, 일반 참여자의 응답 정책 구분
- 검증된 지원 담당자 ID 설정과 기존 해결 관리자 ID 연계
- 관리자·일반 참여자의 기본 `responseRequested=false`
- `@TechFlow-Assistant`와 `/ai` 명시 호출 판정
- 인용문·코드 블록 안의 호출 문자열 무시
- 관리자 답변을 Community Turn 문맥에 저장
- 질문자의 후속 질문에서 기존 관리자 답변을 포함해 AI 분석 재개
- 응답 요청 사유를 Poller 이벤트와 Case 감사 기록에 저장
- 운영 Runbook과 환경 설정 예시 갱신

## 응답 판정표

| 작성자 | 일반 댓글 | 명시적 AI 호출 | 문맥 저장 |
|---|---|---|---|
| 질문자 | AI 응답 | AI 응답 | 예 |
| TechFlow-Assistant | 무응답 | 해당 없음 | 예 |
| 관리자·지원 담당자 | 무응답 | AI 응답 | 예 |
| 일반 참여자 | 무응답 | AI 응답 | 예 |
| 해결 상태 변경 | 일반 응답 없음 | 해당 없음 | KB 절차 수행 |

## 완료 기준

- [ ] 질문자의 질문·추가 자료는 기존과 같이 AI 답변을 생성
- [ ] 관리자의 일반 답변은 저장되지만 AI 답변을 생성하지 않음
- [ ] 관리자의 명시적 AI 호출은 AI 답변을 생성
- [ ] 일반 참여자의 댓글은 기본적으로 AI 답변을 생성하지 않음
- [ ] 인용문·코드 안의 AI 이름은 호출로 오인하지 않음
- [ ] 관리자 답변 이후 질문자 후속 질문에서 관리자 답변 문맥을 사용
- [ ] 해결 답변 선택은 일반 AI 답변 없이 기존 KB 절차만 수행
- [ ] 재시작·재전송 시 중복 답변이 발생하지 않음
- [ ] Poller·Gateway 회귀시험과 실제 Community E2E를 통과
